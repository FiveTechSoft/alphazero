# t0: three-step continuity test
A 3-step start of the es4_char_lm training run (6 layers, d=256) used only to test saving, reloading and continuing. Two continuation runs from the same state gave equal losses, weights and optimizer state (results/t0_res.json, losses 5.10 to 4.19). No scientific capacity is claimed. Files: model.pt, optimizer state in two parts (cat adam.pt.part_* > adam.pt), converted training state (state/).

Hashes (what is and is not established): the stored result's model and optimizer hashes (050baa5d..., d6aa7504...) are content hashes over the nested tensors of the state dicts (dtype plus raw values, sorted keys), not file hashes; file hashes differ by construction (model.pt 07c568c0..., reassembled adam.pt 1a9e7018...). A static recomputation of the same content hash on the published files gave c96d8ee1... (model) and 2a81a56d... (Adam), which do not equal the stored values. The published files are the 3-step saved state; the stored result lists 6 losses per continuation, so its hashes may refer to the state at the end of a longer continuation. This is a possibility, not shown: no identity between the published files and the stored hashes is claimed, and no new run was made. The stored equality flags are given as recorded.
